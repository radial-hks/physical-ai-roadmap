# 贯穿式实践项目

## 项目主线：桌面机器人仿真与学习实验

桌面场景与模拟机械臂的“到达目标点（reach）”作为项目迁移方向，抓取再后置。入门可沿用官方首个机器人示例，P3 可直接以 Cartpole 等简单任务完成核心 RL 验收，不要求先改成机械臂。资产尽量复用官方示例和可用许可证资源，不要求建模完整工厂、购买机器人或自行编写仿真框架。

本项目的“数字孪生”练习是场景组织与仿真建模方法：没有真实设备标定数据时，不声称它是经过实测校准的实体孪生。

不同阶段尽量复用同一任务定义和结果格式，**不假设** GUI 中保存的 USD 可直接作为 Isaac Lab 训练任务，也不假设 RL 与 GR00T 的 embodiment/action space 天然兼容。允许阶段 3 使用官方任务、阶段 4 使用小型独立 BC 数据集，必须明确接口差异，不冒充端到端集成。

## 任务与接口契约

在首次实验记录中填写，后续变更给出原因：

| 项 | 约定 |
|---|---|
| 任务 | 按实际项目填写官方资产/任务 ID；reach 和 Cartpole 是不同任务，不强行共用 schema |
| 单位与坐标 | 距离、角度、时间单位；world/robot/sensor frame；up axis；四元数分量顺序 |
| 观测 | 明确字段、shape、dtype、频率、坐标系；视觉和本体感知分开 |
| 动作 | 明确实际任务的离散/连续动作、范围、频率和控制器；reach 可为关节/末端控制，Cartpole 按该实现的小车控制定义 |
| 成功判据 | 按任务在运行前固定：reach 用末端误差及持续步数，Cartpole 可用存活时长/稳定性；不得看结果后改标准 |
| 失败判据 | 按任务定义越界、失稳、碰撞/数值异常；区分时间截断与任务失败，成功存活到时限不自动算失败 |
| 数据/资产 | 来源、许可、版本、稳定路径或外部存储地址 |
| 对比协议 | 同一任务配置与评估种子；说明是否同一 embodiment 和控制器 |

## P0：可复现环境基线（阶段 0）

- **问题**：当前硬件和软件组合能否完成最小仿真？
- **输入**：[环境清单](environment-windows.md) 与选定版本的官方文档。
- **动作**：盘点配置、选择版本组合、运行最小官方示例、保存日志并重启验证。
- **产物**：`results/p0-environment/` 下的环境/实验记录，小型日志或截图；安装失败也保留完整错误和尝试边界。
- **通过条件**：准确版本与启动方式可查；仿真正常运行并关闭后重新启动；关键限制标出。只读课程不算 P0 通过。

## P1：可解释的物理场景（阶段 1）

- **问题**：场景不仅能显示，还能做可解释的物理行为吗？
- **动作**：搭建最小场景、检查碰撞/质量/关节限制；添加一个传感器；调整一个物理参数或控制参数，重复相同动作。
- **产物**：`results/p1-simulation/`：小型 USD/生成脚本、基线参数、传感器样本、对比记录、复现说明。
- **通过条件**：保存后可重开；解释一次坐标变换；能说明预期与实际行为差异；传感器数据与场景一致。
- **不要求**：首阶段就完成完整 Agent Bootcamp 或自研机器人控制器。

## P2：模块化场景与小型数据集（阶段 2）

- **问题**：场景资产能否复用、变化可控，数据是否可信？
- **动作**：分离机器人、桌面、灯光和场景装配层；制作至少两种配置变体；导出小批量 RGB 和一种辅助模态（depth 或分割标注）。
- **产物**：`results/p2-usd-data/`：layer/引用关系说明、两种变体、数据 manifest 和少量样本。批量数据放外部存储。
- **通过条件**：换根目录后路径可解析；至少一次 USD 结构校验；固定种子可复现数据变化；人工抽检样本与标注对齐；明确数据用途和训练/评估划分。
- **进阶选做**：domain randomization。必须说明随机化参数的物理意义，不能把更多图片等同于更强泛化。

## P3：有基线的 RL 实验（阶段 3）

- **问题**：策略是否学到任务，而不仅是提高训练 reward？
- **动作**：选当前安装版本注册的官方简单任务（如 Cartpole），先 smoke test，再完成同一任务的训练和评估；先小规模并行，记录硬件开销，再决定是否扩大。Reach 属于迁移选做，不是通过 P3 的必要条件。
- **评价协议**：运行前固定任务、训练预算和至少 20 个评估 episode；与随机或规则基线使用相同评估种子。记录成功率、平均回合长度、异常数量；reward 单独报告。此规模是学习验收下限，不代表统计充分。
- **重复性**：至少一个训练种子完成训练和评估，另一个评估种子集合验证是否依赖特定初始条件；多训练种子属于进阶扩展，单次训练结论不得宣称稳健提升。
- **产物**：`results/p3-rl/`：任务 ID、配置、基线与策略评价表、checkpoint 外部地址与摘要、回放记录、吞吐摸底。
- **通过条件**：训练 → 保存 → 新进程加载 → 评估闭环完整；实施至少一次 reward/观测/随机化的单变量对比，保留负结果。
- **迁移边界**：只完成 Cartpole 等官方简单任务时，可以验收 RL 方法学习，但必须明确没有完成桌面机械臂整合；选做 reach 受阻不取消已经有效的 P3 核心验收。

## P4：从 BC 到 VLA 的数据与评估（阶段 4）

### 核心：小模型行为克隆

- **问题**：示范数据、动作表示和评价方式怎样限制学习策略？
- **输入**：可合法使用的公开示范，或由规则控制器/已有策略生成的仿真轨迹。后者明确标为仿真数据，不称真实遥操作。
- **动作**：选择小型状态输入行为克隆模型，按轨迹而非相邻帧拆分训练/验证/测试；记录归一化仅用训练集统计；与常数/均值动作基线比较；离散动作则使用常数类别或频率基线。
- **产物**：`results/p4-imitation/`：数据来源/划分、输入输出 schema、训练配置、独立测试结果、失败样例和一次单变量对比。连续动作记录 MAE/MSE，离散动作记录准确率/交叉熵；明确所选指标。
- **通过条件**：实际跑完小模型训练与独立测试，能解释 BC/RL/VLA 的区别；画出 GR00T 感知输入、语言指令、动作输出与模拟器之间的接口，明确未适配项。
- **评价边界**：离线动作误差或分类指标仅说明拟合能力；有兼容环境时再做闭环成功率评估。没有闭环时必须标“仅离线验证”，不得宣称机器人任务成功。

### 条件实践：GR00T 推理、微调与仿真闭环

先验证官方 checkpoint、数据、embodiment、平台和任务是否匹配。可只选择“加载/单次推理”或“已有模型的仿真评估”；小规模微调是另行选择的后续实验，不因选了推理就必须执行。缺少环境适配时停在该步，不直接跳到微调。

按本次选定的子步骤验收，未执行步骤如实标注：

- **共同记录**：模型与代码 revision、授权/许可、实际资源与成本；付费资源还需批准记录。
- **单次推理**：固定输入、输出动作 schema、运行配置和日志；不据此声称完成仿真闭环。
- **已有模型仿真评估**：固定任务、种子、episode 数、成功/失败判据、实测指标与失败样例，不要求有微调前后对照。
- **微调或数据增强**：只有选择该实验时，才要求相同测试集与任务协议的前后对照。云上只有训练 loss，不算 VLA 端到端验证。

Cosmos 数据增强、物理遥操作、实体机器人/Jetson 部署不属于核心必修。真实 sim-to-real 验证在本计划范围外，不能由视频、仿真或缺口文档替代。

## P5：复现包与学习分享（阶段 5）

- **动作**：按干净会话重新执行代表性实验；整理场景、数据、策略与系统部署的关系；讲清实际做过、只读过和主动裁剪的部分。
- **产物**：`results/p5-summary/`：复现入口、证据索引、关键结论、失败案例、边界与下一步；一篇中文教程或演示讲稿。
- **通过条件**：第三方不看聊天记录能定位配置/证据并尝试复现；所有“已验证”结论有对应记录；不强制修完 Healthcare 或跟完会议材料。
- **分享范围**：先在本私有仓库完成；跨仓库同步或对外发布是独立动作，不自动发布到工作知识库。

## 制品管理

每个实验目录使用 `results/<project-id>/<run-id>/`，`run-id` 是日期加简短主题；记录采用 [实验模板](../templates/experiment.md)。仓库只保留笔记、配置、必要脚本、小型文本资产与少量示例图。大数据、缓存和模型文件不得直接提交，规则见 [results/README.md](../results/README.md)。
