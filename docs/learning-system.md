# 学习体系与推进方式

## 设计说明

本轮把“按课程打卡”调整为“能力 → 实践 → 证据 → 复盘”。保留六阶段编号，便于延续原进度；不扩展成硬件采购、职业转型或公司项目方案。

- **学习目标**：能解释并搭建一个可复现的仿真学习闭环，区分场景资产、物理仿真、数据、策略训练和系统部署的职责。
- **工程背景可复用**：UE C++ / 数字孪生经验用于场景、坐标、资产和性能分析；Python / Agent 经验用于自动化与复现。它们不能替代机器人动力学、RL 和实验评估基础。
- **范围分层**：核心必修要求可验证产物；条件实践受算力、软件支持和预算门禁约束；拓展选修不阻塞核心结业。
- **完成定义**：文档更新不等于学习完成，课程完成不等于能力掌握，仿真成功不等于真实机器人验证。
- **调整方式**：先修改路线或决策，再在 [progress.md](progress.md) 记录原因；不靠勾选掩盖缺口。

| 能力 | 必须会回答的问题 | 练习与验收证据 | 核心目标 / 对应阶段 |

### 按需补基础，不另开一条无限长的前置课程

- 进入阶段 1 前：能读写 Python 配置，理解向量/矩阵、坐标变换、角度与单位。不会的内容通过一个小实验补齐。
- 进入阶段 2 前：掌握 prim/stage 的基本概念和本项目的坐标约定；完整 USD 组合机制在此阶段学习，不要求先精通才启动仿真。
- 进入阶段 3 前：补 MDP、回报、策略、价值函数、PPO 基本直觉；能读训练曲线。暂不要求推导所有算法或从头实现 PPO。
- 进入阶段 4 前：补数据划分、监督学习、行为克隆、归一化及动作表示；先理解小模型，再讨论大模型微调。
- ROS 2 / Isaac ROS：先理解 topic、message、TF、QoS 和控制链路；实装与硬件验证是条件项，不阻塞仿真主线。

## 学习节奏

不设日历截止日期。每个学习循环围绕一个问题，形成可中断、可恢复的最小闭环：

1. **选题**：从 [近期队列](progress.md) 只选一个正在推进的任务，写下要验证的假设。
2. **定向阅读**：读对应官方章节；列出预期现象、版本前提、停止条件，而不是整套资料全部读完。
3. **复现基线**：先运行官方最小示例并记录配置，不同时升级环境和修改算法。
4. **单变量实践**：只改变一个因素，对比结果；失败同样留证据。
5. **复盘归档**：写 [实验记录](../templates/experiment.md)，把能回答/不能回答的问题分开；在进度页更新状态。

可选的常规节奏是每轮约 5–8 小时，分成若干次阅读、实践和复盘；只是可调整的投入预算，不是完成承诺。时间少时缩小实验，不用跳过验证补进度。

### 首批三个学习循环

| 顺序 | 行动 | 明确产物 | 避免的范围膨胀 |
|---|---|---|---|
| 1 | 盘点 Windows，选定兼容的软件组合，运行最小仿真 | P0 环境记录与 smoke test 日志 | 不同时安装所有训练/VLA工具 |
| 2 | 完成基础场景，解释坐标/关节/碰撞，保存并重开 | P1 基线场景与复现步骤 | 不先做复杂工厂/完整机器人系统 |
| 3 | 配置一个传感器，改变一个物理参数，比较结果 | P1 单变量报告与传感器输出 | 不以漂亮截图替代物理正确性 |

每次恢复学习，先读上一条记录的“下一步最小动作”，不重新搜索整套学习路线。

## 验收与范围裁剪

- **知识验收**：能不用复制原文解释关键概念，指出一个失败反例。
- **工程验收**：脚本/配置/资产或外部制品地址完整；另一进程可按说明复现。
- **实验验收**：有基线、评价指标和限制；截图不能替代数值或行为验证。
- **迁移验收**：修改一个变量，预测并解释变化；不要求每次做新项目。

状态词仅使用：`未开始`、`进行中`、`受阻`、`待验收`、`完成`、`已裁剪`。当前状态的唯一记录是 [progress.md](progress.md)，其他文档只定义要求。

- 必修无证据时为受阻或未开始，不能以“文档化缺口”标记完成。
- 条件项可以标已裁剪，但必须链接 [缺口记录](../templates/gap.md)，写触发重开条件及不具备的能力。
- 如果主动修改核心范围，先修订路线并记录范围变更；不能悄悄降低原门槛。
- 环境问题连续两次有记录的尝试仍无新增证据时，转一次根因排查：官方兼容矩阵 → 最小样例 → 支持的替代环境。仍受阻就停在该能力边界，不无限重装。

## Agent 使用边界

复用 VS Code / Copilot / MCP 工具链，不另建“学习管理平台”。Agent 可查文档、生成脚本、解释日志、提出实验对照；学习者必须审阅坐标、物理参数、奖励函数和指标实现。记录 Agent 参与的步骤和人工核验结果。

付费云资源、硬件控制、凭据配置及破坏性操作需要独立确认。不得让 Agent 自动开通 GPU 或把任何仿真脚本直接下发真实机器人。
